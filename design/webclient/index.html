R2P Web Client – Design Mockups

Static HTML design prototypes for the Railway Undertaking Partner Communication web client

Navigation Pages
⚙️
Settings Page

First-run configuration page. User enters the R2P server URL and selects their partner (SBB, BLS, SOB). Settings are persisted in browser localStorage. Redirects to overview on save.

settings.html
📊
Traffic Overview (Verkehrsübersicht)

Sortable, filterable table of all accessible trains. Shows train number, route (from/to), operational day, shared partners, last change, and traffic-light status indicator. Filter by train number, timetable year, and date range.

overview.html
🚆
Traffic View (Verkehrsansicht)

Detail view for a specific train. Shows main variant journey as pearl necklace (read-only). Actions: Share train, Create variant. Lists all variants with state, opens edit or read view. Merge request button per eligible variant.

traffic-view.html
Editor Pages
➕
Create Train (Verkehr anlegen)

Form to create a new train. Includes name, operational day, and an interactive journey editor with pearl necklace visualization. Add stops with "+" buttons, edit stops and activities via modals. Supports journey, rollingStock and other activity types with responsibility and timing.

create.html
✏️
Edit View (Editieransicht)

Edit an existing variant. Pre-populated with the variant's train data. Same pearl necklace editor as create page. Saves as a new version of the variant with a required change comment.

edit.html
👁️
Read View (Leseansicht)

Read-only view of any variant version. Shows train details, pearl necklace journey visualization, and a full activities summary table with plan status, responsibility and timing data. No editing controls are shown.

read-view.html
Modals (accessible via parent pages)
🔗
Share Train Modal

Opens from Traffic View. Lets the user select a partner to share the train with. Only shows partners who don't yet have access. Disabled when all partners are already shared.

traffic-view.html → "Share Train"
⎇
Create Variant Modal

Opens from Traffic View. Enter variant name (max 255 chars) and a required comment. Confirms and redirects to the edit view with the new variant.

traffic-view.html → "New Variant"
⇐
Merge Request Modal

Opens from Traffic View variant list. Proposes a variant's changes to be merged into main. Optional comment. Only shown for own OPEN variants without an existing open merge request.

traffic-view.html → "Merge Request"
📍
Journey Stop Modal

Opens from pearl necklace editor (create/edit pages). Enter stop name (Betriebspunkt), optional location code, arrival and departure times.

create.html / edit.html → "+" or "✏" on stop
📋
Activity Modal

Opens from pearl necklace editor. Select activity type (journey, rollingStock, train.halt.*, etc.), responsibility (type, partner, PlanStatus), timing (arrival/departure). Conditional fields for staff (journey type) or rolling stock details (rollingStock type).

create.html / edit.html → "+" Activity or "✏" on activity
